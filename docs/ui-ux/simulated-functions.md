# Имитируемые функции

| Функция | Что делает прототип | Что реализовать в MVP |
| --- | --- | --- |
| Регистрация вход восстановление | Переходы и локальный список e-mail. Пароль проверяется только по длине, не сохраняется. SMTP не вызывается. | Django AuthService, Argon2id, одноразовый RESET, SMTP, ограничение попыток, отзыв и сроки сессий. |
| Сеанс и владелец | Текущий e-mail в localStorage; данные отбираются по владельцу для демонстрации. | Серверная сессия, Secure/HttpOnly/SameSite, CSRF и проверка всех объектов на сервере; локальная фильтрация не обеспечивает защиту. |
| CRUD контактов дат идей планов | Действия изменяют JSON в localStorage текущего браузера/источника. | PostgreSQL, миграции, API, серверная валидация, версии объектов, квоты и резервирование. |
| Назначение идеи | UI отмечает исходную идею назначенной; повтор не создаёт новый план в текущем состоянии. | Транзакция PostgreSQL и журнал Idempotency-Key; гонки между клиентами и повтор после сетевого сбоя. |
| Бюджет | Суммы переводятся в целое число копеек; UI рассчитывает остаток и перерасход. | NUMERIC(12,2) в БД, Decimal на сервере и повторная проверка входных строк. |
| Памятные даты | Опорная дата прототипа 27.10.2026; ежегодный расчёт, в т. ч. 29 февраля → 28 февраля. | Серверные часы, часовой пояс пользователя, согласование границ интервала. |
| Фото и аккаунт | Вместо фото используются инициалы. Удаление аккаунта сразу очищает его локальные записи. | Загрузка/защищённая выдача JPEG/PNG, контроль 2 МБ, удаление ≤24 ч и реестр удалений для восстановления. |
| Инфраструктура | Есть только статические HTML/CSS/JS; нет Nginx/Gunicorn/Django/PostgreSQL. | Реальный backend, TLS/сессии, журналы 30 суток, pg_dump/pg_restore, RPO/RTO и нагрузочные испытания. |

Post-MVP: напоминания, отдельный экран истории, рекомендации, совместные списки, магазины, массовое назначение и отмена. Они не включены в прототип как готовые функции.

Предложения, ещё не утверждённые в ТЗ: интервалы периода включают конечный день; бюджет назначенной идеи начинается с нуля; допустим выбор любого из трёх статусов; точные ограничения текстовых полей и фото требуют согласования. Эти решения позволяют обсудить UI, но не заменяют решения Q-02–Q-07 из тестовой документации.
