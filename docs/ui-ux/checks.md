# Повторная проверка прототипа

Для ручного просмотра достаточно открыть HTML-файл. Эта инструкция нужна для повторного автоматического прогона 12 UI-проверок.

## Подготовка

Нужны Node.js, установленный Chrome и доступ к интернету для установки Playwright. В терминале из корня проекта выполните:

```powershell
npm install
npm run ui:check
```

По умолчанию скрипт ищет Chrome по пути `C:/Program Files/Google/Chrome/Application/chrome.exe`. Если он установлен в другом месте, укажите полный путь:

```powershell
$env:CHROME_PATH = 'D:/Programs/Google/Chrome/Application/chrome.exe'
npm run ui:check
```

## Результат

Скрипт открывает локальный HTML в изолированных браузерных контекстах, выполняет сценарии и печатает PASS или FAIL. При ошибке завершает работу с ненулевым кодом.

- `artifacts/ui-check/test-results.json` — результат нового прогона.
- `artifacts/ui-check/evidence/` — снимки экранов нового прогона.

Каталог `artifacts` не включён в Git. Исходный протокол в `docs/ui-ux/test-results.json`, Markdown и отчёт Word остаются прежними. Новые результаты нужно оценивать отдельно; скрипт не переписывает отчёт автоматически.

Проверки охватывают пять основных сценариев, ошибки ввода, отказ сохранения, поиск, клавиатуру и адаптивность. Изменение ширины окна не заменяет проверку на реальном телефоне. Серверная безопасность, PostgreSQL и доставка почты в эти тесты не входят.
